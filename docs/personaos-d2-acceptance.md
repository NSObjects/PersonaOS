# D2-4：真库与浏览器验收

本增量在原 D1 浏览器验收之外，增加 **D2 设备类型能力草稿** 的端到端场景。测试使用 CI 启动的一次性 MySQL 8.4、真实 Go API 和 Umi 浏览器 UI，不通过 Mock API 冒充端到端验收。

`tests/e2e/capability_draft_ui.py` 依次执行：

1. 使用初始化的管理员在真实 Chromium 中登录；通过认证后的管理 API 创建共享 Character、A3/A4 设备类型以及四种资源。
2. 在后台「设备类型 → 能力草稿」分别配置 A3 的 Voice、A4 的 Tool/Skill/知识库。
3. 直接查库所对应的 API 持久化结果，确认两个设备类型关联同一 Character 但资源列表完全独立。
4. 重新加载浏览器后再次打开草稿，验证 Voice 选择恢复。
5. 尝试删除仍被引用的资源，确认返回 HTTP 409；尝试把 Voice 错绑到 Tool 字段，确认 HTTP 400 且事务回滚后 A3 原草稿未变化。
6. 全部解除引用，再按外键依赖顺序删除资源、设备类型与角色，确保清理成功。

测试用例由统一 CI 在 D1 浏览器验收后执行；任一用例失败均阻断合并，截图和后端日志按现有 CI 方式保留。

**范围边界：** 本阶段依然只管理未发布的草稿，不涉及设备实例、配置版本、Agent Runtime 或硬件真实上线。
