# PersonaOS D2：设备类型能力配置

## 目标与边界

D1 中 Character 是可复用人格资源，Device Type 是产品型号并通过 `character_id` 引用角色。D2 将音色、Tool、Skill 与知识库作为独立可复用资源，通过设备类型草稿配置关联，避免复制角色，也不把物理硬件能力误认为 Agent 授权。

- 同一个 Character 可以由 A3、A4 等多个 Device Type 共享；它们的能力关联互不影响。
- `has_camera` 仅代表硬件具备摄像头，不能自动开启视觉 Tool；后续还必须满足已关联、运行时支持、设备实际可用、授权和适用的安全策略。
- 音色是独立资源；设备类型可选择一个默认音色或不覆盖角色默认音色。
- Tool、Skill、知识库关联是不同的集合；ID 在各自资源类型内唯一，不跨类型比较。
- 本阶段的草稿配置既不是线上已发布版本，也不是设备实例的实时状态。

## 增量实施

1. **D2-1：领域契约（本 PR）**。引入 `DeviceTypeCapabilities` 草稿值对象，验证设备类型 ID、可选音色、Tool/Skill/知识库 ID 集合的合法性，拒绝非正数与重复 ID，对输入及返回值做防御性拷贝，补齐领域测试。不暴露接口，不落库，不改变运行中设备的行为。
2. **D2-2：独立资源目录**。引入 Voice、Tool、Skill、Knowledge Base 的持久化定义与管理流程，定义资源启停、删除引用保护、敏感配置存储规则及 MySQL 约束。知识库资源的内容导入/检索与此目录管理分离。
3. **D2-3：设备类型草稿关联**。事务性保存设备类型的资源关联；服务器端验证资源存在性、状态及权限；提供受管 API，接入既有登录会话、RBAC、审计与访问授权目录，并同步新增后台管理界面。
4. **D2-4：集成验收**。MySQL 真实数据库、首次初始化与既有库授权升级、HTTP 权限、浏览器 E2E；A3 与 A4 共用角色但关联不同资源，以及并发和失败回滚测试。全部 CI 成功后再合并。

## D3 预留（本阶段不实现）

设备类型配置版本化、发布、回滚、设备实例继承及 Agent Runtime 实际装载由后续迭代负责；不要把后台草稿直接推送给设备。
